# 原工程代码修改说明

本文只记录 `app/redesign` 目录之外，对甲方原工程文件的改动。`app/redesign` 内的新前端、连接层、视觉层、模拟/真实切换器不在本文逐项展开，详见《甲方对接与模拟说明.md》。

当前版本时间：2026-06-14。

## 总览

| 文件 | 当前改动 | 性质 |
| --- | --- | --- |
| `lib/strings.ts` | 扩展语言类型和文案字段，补齐 zh-TW / zh / en / ja / ko 多语言文案 | 长期保留 |
| `lib/strings-context.tsx` | 支持扩展后的语言集合、语言持久化和 `html lang` 同步 | 长期保留 |
| `app/page.tsx` | 首页语言入口适配扩展语言集合 | 长期保留 |
| `app/layout.tsx` | `<html>` 增加 `suppressHydrationWarning` | 长期保留 |
| `components/assistant-ui/thread.tsx` | 增加流式消息自动贴底能力 | 长期保留 |
| `app/ProjectContext.tsx` | 新建/删除项目弹窗改用 CSS 主题变量，跟随当前明暗主题 | 长期保留 |
| `app/ArtifactCanvas.tsx` | 导出 `WelcomeTab`；右侧预览控制区按 redesign 交互改造 | 长期保留，但属于 UI 适配 |
| `app/api/langgraph/route.ts` | 修复 `text` 事件字段名；额外补充本地预览 mock 流 | 字段修复长期保留；mock 可按需删除 |
| `app/api/v1/**` 与 `app/api/_mock/store.ts` | 新增本地模拟接口，用于没有真实后端时验证前端 | 临时/诊断用途 |

说明：当前项目根目录没有 `.env.local`。模拟/真实链路不再依赖空 `.env.local`，而由 redesign 左上角浮动按钮切换。

## 长期保留改动

### `lib/strings.ts`

扩展 `Locale`，从原来的 `en | zh` 扩展为：

```ts
export type Locale = "zh-TW" | "zh" | "en" | "ja" | "ko";
```

同时补齐新增 UI 字段，例如上传附件、设置、语言设置、使用说明、主题切换、新建/删除项目等文案，保证 redesign 与原首页共用同一套多语言来源。

### `lib/strings-context.tsx`

配合 `lib/strings.ts` 扩展后的语言集合，负责：

- 从 localStorage 恢复用户语言。
- 切换语言后写回 localStorage。
- 同步更新 `<html lang="...">`。
- 给原首页和 redesign 提供一致的 `useStrings()` 结果。

### `app/page.tsx`

首页语言切换入口适配 5 种语言。该改动只影响语言选择展示，不改变原首页业务流程。

### `app/layout.tsx`

根 `<html>` 增加：

```tsx
suppressHydrationWarning
```

原因：浏览器翻译插件可能在 React hydration 前给 `<html>` 注入额外属性，例如 `data-immersive-translate-page-theme`，Next.js 开发环境会报 hydration mismatch。该属性只抑制这类外部注入导致的控制台告警，不改变页面结构和业务逻辑。

### `components/assistant-ui/thread.tsx`

增加流式消息自动滚动到底部能力，用于让对话内容持续输出时保持最新内容可见。该逻辑只影响滚动体验，不改变消息数据结构。

### `app/ProjectContext.tsx`

新建项目、删除项目等弹窗从固定深色样式改为使用全局 CSS 变量：

- `--background`
- `--card`
- `--foreground`
- `--muted`
- `--muted-foreground`
- `--border`
- `--primary`
- `--primary-foreground`

这样 redesign 的明暗主题切换后，项目弹窗会跟随当前主题，不再出现“页面是浅色但新建项目窗口仍是黑色”的问题。

### `app/ArtifactCanvas.tsx`

该文件是甲方原有右侧 Artifact 画布组件。当前做了两类改动。

第一类：导出硬件设置组件：

```tsx
export const WelcomeTab: FC = () => { ... }
```

redesign 的“硬件设置”弹窗复用这个组件，避免重新实现一套硬件列表、已连接设备、配对码逻辑。

第二类：右侧预览控制区按当前 redesign 交互调整：

- 移除原来没有内容的“欢迎 / 需求文档 / 界面 / Screens”四个空分区。
- 右侧栏保留三个主操作：预览、构建、在硬件上运行。
- “预览”不再启动硬件预览任务，而是通知 redesign 打开当前选中图片的全屏预览。
- “构建”和“在硬件上运行”仍沿用原有 `POST + GET` 轮询任务模式。
- 构建/运行日志不再使用居中弹窗，而是显示在按钮下方的内联日志区域。
- 硬件设置入口改为日志区域底部的小长条按钮，点击后通过 `redesign-open-hardware-settings` 事件打开 redesign 的硬件设置弹窗。

这部分属于 UI 适配。接口路径、任务轮询格式、硬件列表和配对码数据结构没有改变。

## 本地模拟相关改动

### `app/api/langgraph/route.ts`

这里包含两类改动，需要区分。

长期修复：`type: "text"` 事件必须使用 `content` 字段。前端流式解析读取的是 `content`，如果后端返回 `text`，对话正文不会正常进入前端。

本地模拟：在没有真实后端时，为了让 redesign 能看到需求文档、报告和截图，mock 流临时补充：

- `state`：写入 `requirements`、`app_plan`、`report`、`run_id`。
- `done`：写入 `run_id`、`screen_pngs`、`lap_system_dir`。

如果甲方真实后端已经返回这些事件，可以删除本地补充 mock 段，只保留字段名修复。

### `app/api/v1/**` 与 `app/api/_mock/store.ts`

这些文件是本地模拟后端，用于前端独立演示和排查：

- `/api/v1/projects`、`/api/v1/threads`：项目和线程 mock。
- `/api/v1/runs/{runId}/files/screens/{png}`：截图占位图 mock。
- `/api/v1/runs/{runId}/{kind}`：构建、运行、预览任务 mock。
- `/api/v1/boards`：硬件列表 mock。
- `/api/v1/pair-code`：配对码 mock。
- `/api/_mock/store.ts`：本地内存数据。

甲方接入真实后端时，这些文件可以保留作诊断，也可以按《甲方对接与模拟说明.md》的清单删除。

## 当前没有修改的关键原工程文件

以下文件当前不需要为了 redesign 交互再做额外修改：

- `next.config.ts`
- `app/MyRuntimeProvider.tsx`

真实/模拟切换、URL 改写和诊断逻辑都放在 `app/redesign` 内完成，避免继续扩大原工程改动面。

## 给甲方的结论

当前原工程改动主要分为三类：

1. 多语言、主题、滚动体验等长期前端体验修复。
2. `ArtifactCanvas` 的 redesign UI 适配。
3. 本地 mock 接口，用于无真实后端时验证预览、构建、运行、硬件设置等流程。

其中第 1、2 类建议保留；第 3 类可在真实后端稳定后删除，或保留为本地诊断工具。
