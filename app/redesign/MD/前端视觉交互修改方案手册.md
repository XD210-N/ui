# 前端视觉交互修改方案手册

> 这份文档写给**后续改前端视觉/交互的人（设计师或 AI）**。目标：把"我想改某个视觉/交互效果"翻译成"具体动哪个文件、怎么写代码"，并保证**不影响后端功能、不破坏前后端对接、不卸载组件**。
>
> 配套阅读：`修改代码注意事项.md`（硬性底线）、`我方需求与模拟对接策略.md`（整体策略）。本手册是它们的**实操落地版**。
>
> 用法：改动前先在下面「分类速查表」找到你的需求类型，按对应方案改。**若表里没有你的需求**，按文末「新需求怎么办」流程先梳理安全改法，再把它补进本手册。

---

## 〇、先记住三条铁律（违反 = 影响功能）

1. **只改 `app/redesign/ui/` 和 CSS，不碰 `app/redesign/bindings/` 的逻辑、不碰 `app/` 下甲方组件。**
2. **隐藏用 CSS（`translate`/`opacity`/`display`），绝不用条件渲染卸载**（`{open && <X/>}` 是禁忌）。
3. **不删功能入口、不改请求/数据流。** 样式只决定"长什么样、怎么出现"，不决定"数据怎么走"。

判断法：需求是「好看点 / 换出现方式 / 挪位置 / 改动画 / 改尺寸」→ 纯样式，安全。需求是「让某东西在某条件下出现/消失/不加载」→ 涉及挂载或功能，按本手册对应方案做（隐藏而非卸载）。

## 二、各方案详解

### 方案 1：改颜色 / 字体 / 圆角 / 阴影 / 主题配色

**改哪里**：`app/redesign/ui/AppShell.tsx` 底部 `<style jsx global>` 里的 CSS 变量块。

- 亮色：`.redesign-shell { --background / --foreground / --card / --primary / --border / --muted ... }`
- 暗色：`.redesign-shell[data-theme="dark"] { 同名变量另一套值 }`

**怎么改**：只改变量值，不动用到变量的地方。例如把主色从橙色换成蓝色，只改 `--primary: #ff5a13` → `#2563eb`，所有引用 `var(--primary)` 的按钮/高亮自动跟着变。

**为什么安全**：CSS 变量是纯视觉 token，组件结构和数据流完全不知道颜色是什么。改完暗色配色也只动 `[data-theme="dark"]` 那一块。

**别做**：不要把颜色写死进组件 className（如 `bg-[#ff5a13]`），要用 `bg-[var(--primary)]`，否则主题切换时不跟随。

---

### 方案 2：改抽屉 / 弹窗的出现方式（动画、方向、速度）

**改哪里**：对应组件根节点的 className 过渡类。

- 右抽屉：`AppShell.tsx` 里那个 `fixed inset-y-0 right-0 ...` 的 `<section>`，开关靠 `rightOpen ? "translate-x-0" : "translate-x-full"`。
- 左抽屉：`fixed inset-y-0 left-0 ...` 的 `<aside>`，`leftOpen ? "translate-x-0" : "-translate-x-full"`。
- 说明书弹窗：`ManualModal.tsx` 的 `open ? "translate-y-0 scale-100" : "-translate-y-8 scale-[0.98]"`。

**怎么改**：
- 换方向：把 `translate-x-full`（从右滑）改成 `translate-y-full`（从下滑）等。
- 换速度/缓动：改 `duration-300`、`ease-out`。
- 换成淡入：把 transform 类换成 `opacity-0 / opacity-100`。
- 换成缩放：用 `scale-95 / scale-100`。

**为什么安全**：开/关状态变量（`rightOpen` 等）保持不变，组件**始终挂载**，你只改"关闭态长什么样"。动画纯 CSS。

**关键铁律**：那个三元表达式的**两个分支都必须是 CSS 类**（一个开态、一个关态），永远不要改成 `rightOpen && <section>`——那会卸载 ArtifactCanvas，丢预览状态。关态记得保留 `pointer-events-none` 避免隐藏后还能点。

---

### 方案 3：改窗口形式（尺寸 / 位置 / 宽度占比 / 居中 / 全屏 / 布局比例）

**改哪里**：对应容器的尺寸/定位 className。

- 右抽屉宽度：`AppShell.tsx` 右侧 `<section>` 的 `w-[83.333vw]`，以及主区被压缩的 `rightOpen ? "w-[16.666vw]" : "w-full"`。改这两个数值即调整"展开后预览占多宽 / 主区留多窄"。
- 左抽屉宽度：左侧 `<aside>` 的 `w-[280px]`。
- 说明书弹窗大小：`ManualModal.tsx` 的 `max-w-[920px]`、`max-h-[84vh]`。
- 按钮尺寸：`size-12` 之类。

**怎么改**：直接改 Tailwind 尺寸值。想让右抽屉全屏 → `w-[83.333vw]` 改 `w-screen`、主区 `w-[16.666vw]` 改 `w-0`。想让弹窗更大 → 改 `max-w`。

**为什么安全**：尺寸和定位是纯布局，不碰任何状态或数据。

**注意**：主区宽度和右抽屉宽度是配套的（一个压缩一个展开），改的时候两边一起想，别让它们重叠或留缝。

---

### 方案 4：改按钮位置 / 图标 / hover

**改哪里**：对应按钮的 className 和图标组件。

- 左下角项目入口、右上角预览按钮：`AppShell.tsx` 里 `fixed bottom-6 left-6`、`fixed right-6 top-6` 的 `<button>`。改定位类即挪位置。
- 图标：从 `lucide-react` 换 import 的图标组件（如 `<Menu>` 换 `<PanelRight>`）。
- 设置浮标和子按钮：`SettingsDock.tsx`。

**为什么安全**：按钮的 `onClick`（如 `setRightOpen`、`setLeftOpen`）保持不变，你只改它的外观和位置。**改样式时不要动 `onClick`**。

---

### 方案 5：改聊天区 / 输入框 / 消息外观

**改哪里**：`AppShell.tsx` 的 `<style jsx global>` 里那批 `.aui-*` 选择器（甲方 assistant-ui 组件的样式钩子）。

- 输入框外壳：`[data-slot="aui_composer-shell"]`（圆角、背景、阴影、内边距）
- 输入文字：`.aui-composer-input`
- 发送按钮：`.aui-composer-send`
- 上传按钮：`.aui-composer-add-attachment`
- 欢迎标题/副标题：`.aui-thread-welcome-message h1 / p`
- 聊天背景：`.aui-thread-root`（用 `--thread-bg` 变量）

**怎么改**：改这些选择器里的 CSS 属性即可（颜色尽量用 `var(--...)`）。

**为什么安全**：这些是给甲方真实组件"套样式"，不改组件本身的行为。甲方的 `Thread`/`Composer` 照常工作，只是外观变了。

**别做**：不要去改甲方组件文件（`components/assistant-ui/*`），只在 redesign 的全局样式里覆盖。不要改 `data-slot` / `.aui-*` 这些选择器名（那是甲方定的钩子，改名就选不中了）。

---

### 方案 6：改默认开/关状态、自动出现时机 ⚠️半功能

**改哪里**：

- 默认开/关：`AppShell.tsx` 的 `useState(false)`（`leftOpen`/`rightOpen`/`manualOpen` 的初值）。想默认打开右抽屉就改成 `useState(true)`。
- 自动拉出时机：`AppShell.tsx` 里订阅 canvasStore 的那段 `previewReady`（当前是 `runComplete && screenPngs.length>0`）。

**怎么改 / 注意**：
- 改默认开关初值：安全，纯前端状态。
- 改自动拉出条件：这是**功能联动**，它读的是后端数据（canvasStore 的 `runComplete`/`screenPngs`）。可以改触发条件（比如改成"有 requirements 就拉出"），但**不要改 canvasStore 本身**，只改"读到什么就展开"的判断。改完要保证仍是"上升沿只触发一次"，否则用户关了又被强制弹开。

---

### 方案 7：新增纯展示的视觉元素（装饰 / 角标 / 提示文字 / 加载态外观）

**改哪里**：在 `app/redesign/ui/` 对应组件的 JSX 里加元素，或新建一个纯展示组件放进 `ui/`。

**怎么改**：随便加 `<div>`/`<span>`/图标/动画，只要它不依赖后端数据、不替代现有功能。文案优先走 `useStrings()`（多语言），临时诊断类文字可直接写。

**为什么安全**：纯展示元素不接数据、不接事件，加多少都不影响功能。

**注意**：如果这个新元素要显示后端数据（如"当前 run 状态"），那它就不是纯展示了，要走方案 8 读已有 store，不要自己造数据。

---

### 方案 8：新增一个要触发功能的按钮 ⚠️接线

**改哪里**：UI 在 `ui/` 层，但触发逻辑必须**接已有的 hook/store/runtime**，不要自己写业务逻辑。

**怎么改**：
- 要切换语言 → 接 `useSetLocale()`
- 要切主题 → 接 `useRedesignTheme`
- 要开关抽屉 → 接 AppShell 的 `setLeftOpen`/`setRightOpen`
- 要发消息/操作线程 → 必须用甲方的 runtime/primitive（参考 `bindings/` 里现有接法），**不要自己 fetch**

**为什么这样**：所有功能甲方都已实现，新按钮只是多一个触发入口，复用现有能力即可。自己 fetch 或自己写状态 = 绕过甲方对接 = 破坏一致性。

---

### 方案 9：让某组件"先不显示" ⚠️最易踩雷

**正确做法**：用 CSS 隐藏，组件保持挂载。

```tsx
<section className={show ? "block" : "hidden"}>{slot}</section>
// 或 opacity-0 + pointer-events-none，或 translate 移出屏幕
```

**禁忌**：

```tsx
{show && slot}   // ❌ 卸载组件：丢状态、断订阅、重置运行中的请求
```

**为什么**：`Thread`/`ArtifactCanvas`/`MyRuntimeProvider` 这些一旦卸载，正在进行的对话、预览、历史、轮询全部归零。隐藏 ≠ 卸载。任何"暂时不显示"的需求都用隐藏实现。

---

## 三、新需求怎么办（表里没有时的流程）

遇到本手册没覆盖的视觉/交互需求，按这个流程，**不要凭感觉直接改**：

1. **判定类型**：它只改"外观/位置/动画/尺寸"？→ 纯样式，照方案 1-5、7 的思路在 `ui/` 层或 CSS 改。
2. **是否触碰挂载**：需求是否要"让某组件出现/消失/不加载"？→ 用方案 9 的隐藏方式，**绝不卸载**。
3. **是否触碰数据/功能**：需求是否要读后端数据、发请求、改状态？→ 用方案 6/8，接已有 store/hook，不自己造数据、不自己 fetch。
4. **梳理安全改法**：写下"动哪个文件、改哪几行、为什么不影响功能/对接"。
5. **补进本手册**：把这个新需求作为一条新「方案」追加到第二节，更新第一节速查表。保持本手册是"所有前端改动安全改法"的唯一索引。

> 核心心法：**视觉层（ui/ + CSS）和功能层（bindings/ + 甲方组件）严格分离。** 你在视觉层怎么改都安全；一旦需求要碰功能层，就只"接线"不"重写"，只"隐藏"不"卸载"。
