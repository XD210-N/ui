# 甲方对接与模拟说明

本文写给甲方团队，说明当前 redesign 前端如何连接真实后端、如何切换到本地模拟数据、哪些 mock 只是为了本地演示，以及真实接入时应该保留或删除哪些内容。

当前版本时间：2026-06-14。

## 当前默认状态

当前代码默认进入“模拟数据”模式。

原因：我方本地没有甲方真实后端服务，默认模拟可以让评审人员直接看到需求文档、画布截图、构建日志、运行日志和硬件设置流程。

切换入口在 redesign 页面左上角：

- 按钮显示“模拟数据”时，当前请求走本地 mock。
- 点击后切到“真实后端”，页面会刷新，所有 `/v1/*` 和 `/langgraph/*` 请求走真实后端。
- 按钮左侧小把手可拖动，位置会保存在 localStorage。
- 真实模式下会出现“诊断”入口，可检查关键接口是否连通。

对应代码：

- `app/redesign/ui/BackendModeFloating.tsx`
- `app/redesign/bindings/backendMode.ts`
- `app/redesign/bindings/backendDiagnostics.ts`
- `app/redesign/ui/BackendDiagnosticsModal.tsx`
- `app/redesign/page.tsx`

## 真实后端地址

真实模式使用：

```ts
process.env.NEXT_PUBLIC_SAAS_URL ?? "http://localhost:8000"
```

也就是说，甲方环境只需要配置：

```bash
NEXT_PUBLIC_SAAS_URL=http://真实后端地址
```

如果未配置，则真实模式默认请求 `http://localhost:8000`。

当前版本已经取消“真实请求失败后自动回落 mock”的逻辑。这样做是为了避免误判：切到真实后端后，如果真实服务不可用，前端会明确暴露连接失败，而不是悄悄显示模拟数据。

## 请求改写规则

### 模拟数据模式

模拟模式下：

- `/v1/*` 保持相对路径，请求 Next.js 本地 API。
- `/langgraph/*` 保持相对路径，请求 Next.js 本地 API。
- 绝对地址里的 `${NEXT_PUBLIC_SAAS_URL}/v1/*` 和 `${NEXT_PUBLIC_SAAS_URL}/langgraph/*` 会被改写成本地相对路径。

这样甲方原前端里使用绝对后端地址的请求，也能在本地 mock 下跑通。

### 真实后端模式

真实模式下：

- 相对 `/v1/*` 会补成 `${NEXT_PUBLIC_SAAS_URL}/v1/*`。
- 相对 `/langgraph/*` 会补成 `${NEXT_PUBLIC_SAAS_URL}/langgraph/*`。
- 已经是绝对地址的真实请求保持真实地址。

这个处理用于避免原工程里“项目接口走相对路径，被 Next rewrite 打到本地 mock；线程和对话接口走真实后端”的混合链路问题。真实模式下，项目、线程、对话会统一指向真实后端。

## 当前 mock 接口清单

### 1. 聊天与预览主链路：`POST /langgraph`

前端期望 SSE 事件包括：

```ts
{ type: "text", content: string }
{ type: "state", requirements, app_plan, report, run_id }
{ type: "done", run_id, screen_pngs, lap_system_dir }
{ type: "error", message }
```

本地 mock 会模拟文字流、需求文档、报告和截图文件名，让 redesign 能展示完整项目操作界面。

重要修复：`type: "text"` 的正文应使用 `content` 字段。这个修复建议保留。

### 2. 截图文件：`GET /v1/runs/{runId}/files/screens/{png}`

本地 mock 返回 SVG 占位图，用于验证画布图片布局、选中态、拖动和全屏预览。

当前前端还加了最后兜底：如果图片请求失败，会用前端生成的 SVG data URL 占位，避免画布出现空白或被压扁。

真实后端接入后，应返回真实图片文件。当前 screen 路径格式为：

```text
/v1/runs/{runId}/files/screens/screen_1.png
```

例如：

```text
/v1/runs/mock-run-001/files/screens/screen_1.png
```

### 3. 构建和运行任务：`/v1/runs/{runId}/{kind}`

当前支持：

- `build`
- `deploy`
- `preview-hardware`（接口仍保留，当前 redesign 的“预览”按钮已改为打开选中截图全屏，不再启动该任务）

调用方式：

1. `POST /v1/runs/{runId}/{kind}` 启动任务。
2. 每 2 秒 `GET /v1/runs/{runId}/{kind}` 轮询。
3. 前端读取 `{ state, step, log, returncode }` 并把日志显示在右侧按钮下方。

当前 UI 中：

- “构建”显示构建日志。
- “在硬件上运行”显示部署/运行日志。
- 日志不再使用居中弹窗，而是内联显示在按钮下方。

### 4. 硬件列表：`GET /v1/boards`

`WelcomeTab` 每 10 秒轮询一次，前端期望返回：

```ts
{
  supported: SupportedBoard[];
  connected: ConnectedProxy[];
}
```

`supported` 用于展示可选目标硬件，`connected` 用于判断“在硬件上运行”是否可点击。

### 5. 配对码：`POST /v1/pair-code`

前端期望返回：

```ts
{
  pair_code: string;
  expires_at: string;
  pair_url: string;
  daemon_command: string;
  device_name: string;
}
```

该接口供硬件设置中的“生成配对码”使用。

### 6. 项目和线程：`/v1/projects`、`/v1/threads`

本地 mock 提供项目、线程、打开项目、删除项目等基础数据，保证没有真实后端时页面能进入完整操作流程。

真实模式下这些请求会被统一改写到 `${NEXT_PUBLIC_SAAS_URL}`，不会再和本地 mock 混用。

## 当前 redesign 前端行为

### 进入项目操作界面

用户发送消息后，只要收到需求文档、方案、报告、完成事件或截图列表，页面会进入项目操作界面，并打开右侧需求文档区域。

聊天流式输出期间，画布上的上一轮截图不会被清空；新一轮截图完成后再替换，避免输入消息后图片突然消失。

### 需求文档自动滚动

右侧需求文档区域在流式输出新内容时，会自动滚动到底部，保证最新内容始终可见。

### 画布图片

当前画布图片行为：

- 默认选中第一张图。
- 点击另一张图会切换选中态。
- 选中图片有微亮边框和阴影。
- 图片可在画布上拖动。
- 图片不会带额外控件，不显示多余预览按钮。
- 图片请求失败时使用前端 SVG 占位兜底，保证客户环境路径未就绪时也不会空白。

### 全屏预览

右侧“预览”按钮会打开当前选中图片的全屏预览：

- 全屏只显示图片。
- 图片等比例放大。
- 宽或高至少有一个方向贴近屏幕边界。
- 不裁切，不超出屏幕。
- 按 Esc 退出。

### 构建和运行

“构建”和“在硬件上运行”的输出显示在按钮下方的内联日志区域。颜色跟随当前主题，并按按钮类型使用不同强调色。

### 硬件设置

硬件设置入口在右侧日志区域底部，是一个小长条按钮。点击后打开 redesign 中央硬件设置弹窗，弹窗内容复用甲方原 `WelcomeTab`，包括支持硬件、已连接设备和配对码。

## 交付给甲方时如何处理 mock

如果甲方希望保留诊断能力，可以保留当前切换器和 mock。这样在真实后端异常时，可以一键切回模拟数据，对比前端渲染链路是否正常。

如果甲方希望得到完全纯净的真实后端版本，可以删除以下临时项：

| 项 | 文件 / 改动 | 说明 |
| --- | --- | --- |
| 1 | `app/api/langgraph/route.ts` 中本地补充 `state/done` 的 mock 段 | 删除后由真实后端返回需求、报告、截图列表 |
| 2 | `app/api/v1/runs/[runId]/files/[...path]/route.ts` | 删除本地截图占位图 |
| 3 | `app/api/v1/runs/[runId]/[kind]/route.ts` | 删除构建/运行/预览任务 mock |
| 4 | `app/api/v1/boards/route.ts` | 删除硬件列表 mock |
| 5 | `app/api/v1/pair-code/route.ts` | 删除配对码 mock |
| 6 | `app/api/v1/projects/**`、`app/api/v1/threads/**`、`app/api/_mock/store.ts` | 删除本地项目和线程 mock |
| 7 | `app/redesign/ui/BackendModeFloating.tsx`、`BackendDiagnosticsModal.tsx`、`bindings/backendMode.ts`、`bindings/backendDiagnostics.ts`、`page.tsx` 中对应挂载 | 删除真实/模拟切换器和诊断工具 |

删除第 7 项后，需要确保真实后端地址在原工程里有统一配置，且项目、线程、对话三类请求都指向同一个真实后端。

## 如果希望默认进入真实后端

当前代码默认模拟，位置在：

```ts
// app/redesign/bindings/backendMode.ts
const DEFAULT_MODE: BackendMode = "mock";
```

如果甲方正式环境希望默认进入真实后端，把它改为：

```ts
const DEFAULT_MODE: BackendMode = "real";
```

也可以不改代码，直接在页面左上角按钮切到“真实后端”。用户选择会保存在浏览器 localStorage。

## 给甲方的结论

当前 redesign 前端已经可以在两种模式下工作：

- 模拟数据模式：用于无后端演示、UI 评审和前端交互验证。
- 真实后端模式：用于连接甲方 `NEXT_PUBLIC_SAAS_URL`，并明确暴露真实接口是否可用。

mock 的目的不是替代真实后端，而是把前端交互、图片画布、需求文档、构建日志、硬件设置这些体验先完整展示出来。真实后端接入后，保留或删除 mock 都可以，不影响 redesign 主界面代码。
