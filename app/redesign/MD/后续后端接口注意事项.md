# 后续后端接口注意事项

> 本文件用于后续接手时快速判断：哪些后端/接口相关代码已经接好，哪些只是本地数据模拟，后续修改应尽量只动 `app/redesign/` 内的前端视觉与交互文件。

## 当前结论

- 当前“真实接口版”和“模拟数据版”的前端对接主链路已经基本完成。
- 后续若只是调整窗口、按钮、拖拽、收起、流式视觉、画布动效、控件位置等体验，原则上不需要再新增后端连接。
- 后续主要修改范围应限制在：
  - `app/redesign/ui/`
  - `app/redesign/bindings/` 中必要的轻接线
  - `app/redesign/MD/` 文档
- 不要为了做视觉效果去改甲方核心接口逻辑、请求地址、SSE 解析、Project/Thread runtime。

## 必须理解的模拟原则

模拟版只模拟“数据来源”，不模拟“前端接口逻辑”。

也就是说：

- 请求 URL、HTTP 方法、body、返回字段，应与甲方真实前端期望一致。
- 前端请求构造和返回解析，尽量使用甲方工程里已有代码。
- mock 路由只负责返回符合契约的假数据，用来证明前端接口代码没有问题。
- 甲方接真实后端后若出问题，可以对照 mock 返回格式排查：是后端字段/路由不一致，还是环境地址配置不一致。

禁止：

- 在 redesign 前端里自己 `fetch` 后端绕过甲方 runtime。
- 自己造数据塞进真实 runtime/store。
- 改 `MyRuntimeProvider` / `ProjectContext` / `canvasStore` 的业务逻辑来迁就 UI。
- 用假组件替代 `Thread`、`ArtifactCanvas`、`Composer`、`ProjectProvider`、`ProjectGate`。

## 后端和接口相关关键文件

### 真实运行时与 SSE 解析

- `app/MyRuntimeProvider.tsx`
  - 甲方真实对话运行时。
  - 负责发线程/对话请求、读取 `/langgraph` SSE、解析 `text/state/done/error`。
  - 后续通常不要改。

- `app/canvasStore.ts`
  - 甲方 artifact 数据的模块级 store。
  - 字段包括 `requirements`、`appPlan`、`report`、`runId`、`runComplete`、`screenPngs`、`lapSystemDir`。
  - redesign 可以只读它做视觉展示；不要改它的数据结构和写入语义。

### 项目与线程

- `app/ProjectContext.tsx`
  - 甲方项目列表、打开项目、新建项目、ProjectGate 逻辑。
  - 当前策略跟随甲方“默认已有项目”方案。
  - 后续除非确认真后端新用户无默认项目，否则不要动。

- `components/assistant-ui/thread.tsx`
  - 甲方真实 Thread/Composer。
  - 已有长期改动：`ThreadPrimitive.Viewport` 增加 `autoScroll`。
  - 不要为了隐藏/切换 UI 卸载它。

### 右侧 Artifact 与硬件

- `app/ArtifactCanvas.tsx`
  - 甲方真实右侧 artifact 面板。
  - 展示 welcome/prd/slint/screens 四类内容。
  - 已有长期改动：`WelcomeTab` 增加 `export`，供 redesign 的硬件设置弹窗复用。
  - 后续阶段 3 的需求文档独立窗应优先在 `app/redesign/ui/` 新增展示层读取 `canvasStore`，不要直接重写这里。

- `app/boardStore.ts`
  - 硬件选择状态。
  - `WelcomeTab` 会使用它，redesign 不应另起一套硬件状态。

## 当前 mock 路由和含义

这些 mock 是为了本地没有甲方后端时验证前端渲染和交互，PR/交付前按 `甲方对接与模拟说明.md` 清理。

- `app/api/langgraph/route.ts`
  - 甲方自带 mock。
  - 永久保留修正：`type:"text"` 字段使用 `content`，与 `MyRuntimeProvider` 读取一致。
  - 临时 mock 段：补发 `state` 和 `done(screen_pngs)`，用于本地验证需求/方案/报告/Screens。

- `app/api/v1/runs/[runId]/files/[...path]/route.ts`
  - 临时占位图路由。
  - 用于让 Screens 图片 URL 能显示假图。

- `app/api/v1/runs/[runId]/[kind]/route.ts`
  - 临时预览/构建/部署任务 mock。
  - 模拟 `preview-hardware`、`build`、`deploy` 的 POST + GET 轮询结果。

- `app/api/v1/boards/route.ts`
  - 临时硬件列表 mock。
  - 返回 `supported` 和 `connected`，供 `WelcomeTab`/硬件设置使用。

- `app/api/v1/pair-code/route.ts`
  - 临时配对码 mock。
  - 返回 `pair_code`、`expires_at`、`pair_url`、`daemon_command` 等。

## redesign 内与后端切换相关文件

- `app/redesign/bindings/backendMode.ts`
  - 真实/模拟切换器的 fetch 拦截器。
  - 默认环境感知：有 `NEXT_PUBLIC_SAAS_URL` 走真实；没有则本地走模拟。
  - 真实模式会把项目相对请求补成 `SAAS_URL` 绝对地址，规避甲方原工程项目请求被 rewrite 到本地 mock 的问题。

- `app/redesign/bindings/backendDiagnostics.ts`
  - 后端连通性诊断。

- `app/redesign/ui/BackendModeFloating.tsx`
  - 左上角真实/模拟模式入口。

- `app/redesign/ui/BackendDiagnosticsModal.tsx`
  - 后端诊断弹窗。

- `app/redesign/page.tsx`
  - 调用 `installBackendModeInterceptor()`。
  - `BackendModeFloating` 放在 `ProjectGate` 外，防止真实后端连不上时无法切换。

这些属于诊断工具。甲方真实环境可保留，也可在纯净版中按文档删除。

## 后续阶段的接口判断

### 阶段 3：需求文档独立窗

不需要新增后端接口。

正确做法：

- 在 `app/redesign/ui/` 新增或修改视觉组件。
- 只读 `canvasStore.requirements`、`canvasStore.report`、`canvasStore.appPlan`。
- “流式逐字输出”在 redesign 层做打字机动画，因为后端 `state` 字段是整体替换，不是逐字事件。
- 收起/恢复用 CSS transform/opacity/pointer-events，不卸载组件。

当前第一版实现：

- `app/redesign/ui/ProjectDocumentPanel.tsx`
- `app/redesign/ui/AppShell.tsx` 内挂载 `<ProjectDocumentPanel projectMode={projectMode} />`
- 该组件只读 `canvasStore`，不新增后端连接。
- 原 `ArtifactCanvas` 仍然挂载，作为甲方真实 artifact/任务/硬件功能面板。

### 阶段 4：Screens 居中画布

通常不需要新增后端接口。

正确做法：

- 读 `canvasStore.screenPngs`、`canvasStore.runId`、`canvasStore.lapSystemDir`。
- 图片 URL 格式沿用甲方 `ArtifactCanvas` 的规则：`/v1/runs/{runId}/files/screens/{png}`。
- 在 `InfiniteCanvas` 上做视觉放置、浮现、拖拽，不改图片数据来源。

### 阶段 5：无项目新建引导

默认不做。

只有甲方确认真后端新用户可能返回空项目列表时，才需要补这一阶段。若要做，也应复用 `ProjectContext` 已有能力，不重写项目接口。
