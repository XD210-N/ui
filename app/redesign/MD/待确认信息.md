## 1. ⬜ 新用户首次进入是否有默认项目？（影响首页能否直接聊天）

**背景**：用户要求首页一进来就能聊天、左侧项目窗做成毛玻璃悬浮、聊天全屏。这成立的前提是"一进来就已经在某个项目里"。

**已查证（甲方代码事实）**：
- 甲方架构是"先有 activeProject 才渲染对话界面"——`ProjectGate` 在 `!activeProject` 时 `return null`，只弹"新建项目"全屏窗（`ProjectContext.tsx`）。
- 甲方**mock 后端**在 `app/api/_mock/store.ts` 里**预置（seed）了一个默认项目 `demo-project`**，注释原话："Seed one default project so the UI loads immediately without a create dialog"。
- 前端 `ProjectProvider` 挂载时拉项目列表 → 列表非空 → 自动 `openProject` 第一个 → 直接进对话。
- **所以甲方"一进就能聊"靠的是后端保证项目列表非空。**

**我方当前怎么处理**：跟随甲方方案——默认已有项目（demo-project），不自己做"发第一句才建项目"的逻辑。首页项目窗改毛玻璃悬浮、聊天全屏，都属纯视觉。新建项目功能（`requestCreateDialog` / `CreateProjectDialog`）完全保留不动。

**需要甲方确认**：
- 贵方**真后端**在新用户、一个项目都没有时，`GET /v1/projects` 返回的是空列表，还是也会保证至少有一个默认项目？
- 若返回空列表 → `ProjectGate` 会 `return null`、弹新建窗，我方"首页直接全屏聊天"的前提不成立。

**若答案是"真后端可能返回空列表"，我方要怎么改**：
- 需在首页聊天窗之前，用 redesign 自己的界面设计一个"新建项目"入口/引导（纯前端，调甲方 `createProject`），覆盖"无项目"场景。这会回到原先"阶段 5 首句/前置建项目"的接线改动。
- 因此本条结论直接决定要不要做那一块。**优先级高，请尽早确认。**

## 2. ⬜ 真后端 SSE 助手文字字段是否为 `content`？

**背景**：甲方前端 `MyRuntimeProvider` 读 `event.content`，但甲方自带 mock 发的是 `event.text`（字段不一致 bug，我方已在 mock 里修正为 content）。

**需要甲方确认**：真后端推送助手文字时，字段名是 `content` 还是 `text`？若是 `text`，真实链路下助手回复正文也会空白，需后端改成 `content`（与前端一致）。

## 3. ⬜ 项目请求是否应走真后端？（今早 404 根因）

**背景**：甲方原工程项目请求 `/v1/projects` 用相对路径，被 `next.config.ts` rewrite 固定转去前端自带 mock，到不了真后端；而线程/对话用 `${SAAS_URL}` 绝对地址走真后端。两条链路分裂导致 `Conversation not found`（404）。详见 `甲方对接与模拟说明.md` 头号排查项。

**我方当前怎么处理**：真实/模拟切换器的真实模式拦截器已把项目相对请求补成 `${SAAS_URL}` 绝对地址，自动规避。

**需要甲方确认**：贵方真后端是否提供 `/v1/projects` 系列接口？纯净版（移除切换器）下，需贵方把 `ProjectContext` 改绝对地址或把 rewrite 指向真后端。
