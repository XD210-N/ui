> 本文档是「以项目为核心的高级交互重构」的总方案与分步执行计划。写给执行的人（AI/开发）和审阅的人（甲方/我方）。
>
> **执行原则**：先读本文确认流程 → 一步一步做 → 每步用户自行运行看效果 → 用户说 OK 才进下一步。**任何未处理到的控件/窗口都必须继续显示、能正常用**，并在每步末尾告知"还有哪些没处理"。

## 一、需求总览（用户原话拆解）

1. **以项目为核心**：跟随甲方"默认已有项目"方案（后端保证项目列表非空，前端自动打开第一个，一进就能聊）。**不做"发第一句才建项目"的时序倒置**。首页左侧项目窗做成毛玻璃悬浮、聊天全屏；**新建项目功能完全保留**。（依赖：真后端需保证新用户有默认项目，见 `待确认信息.md` 第 1 条。）
2. **形态切换**：后端返回文字以外内容（state/done）时，不再是"右抽屉压缩拉出"，而是整个界面**形态变成项目操作面板**：中间文字说明隐去，对话窗变成项目内沟通界面。
3. **不能左右分割**：左侧聊天窗做成**毛玻璃悬浮**在项目操作面板之上的效果，定一个合适比例。整体苹果质感、高级美观。
4. **硬件设置**（原"欢迎"tab）：改名"硬件设置"，放进项目操作面板里做一个按钮弹出。
5. **需求文档窗口独立**：done 时先在右侧浮现毛玻璃悬浮窗，**流式输出需求文档内容**，显示完才显示图片；后续新内容直接流式追加（只第一次等图片）。可点击关闭 → 拽回右下角极简控件；点控件 → 拽出恢复。**只是视觉隐藏，组件不卸载，后台一直在。**
6. **需求文档 + 流式文本合并**：若第三窗口（slint/界面）后续只是流式文本，就和需求文档放一个窗口，用标签切换。
7. **Screens（界面截图）**：等需求文档流式输出完 → 以浮现动画出现在**页面中央**。整屏是**网格背景的无边界画布**，图片在画布上，左右两侧会话窗+信息窗都是悬浮在画布上的半透明控件。

## 二、关键时序核查结论（已读甲方源码确认）

### ✅ 决定：跟随甲方"默认有项目"方案，不做"发第一句才建项目"

甲方"一进首页就能聊天"的真相（已查证）：

- 甲方 mock 后端在 `app/api/_mock/store.ts` **预置（seed）了一个默认项目 `demo-project`**，注释原话："Seed one default project so the UI loads immediately without a create dialog"。
- 前端 `ProjectProvider` 挂载 → 拉项目列表 → 非空 → 自动 `openProject` 第一个 → activeProject 就绪 → `ProjectGate` 放行 → 直接进对话。
- 即：甲方"一进能聊"靠的是**后端保证项目列表非空**，不是绕过项目。

**决定**：我方跟随甲方方案——默认已在一个项目里。**不再做"发第一句话才建项目"的时序倒置接线**（原阶段 5 砍掉）。这样：

- 首页"项目窗毛玻璃悬浮 + 聊天全屏" = **纯视觉**（activeProject 已就绪、对话界面已渲染，只改布局外观）。
- **新建项目功能完全保留**（甲方 `requestCreateDialog` / `CreateProjectDialog` 原样不动）。
- 整套重构的最大风险点（碰 ProjectGate 时序）被移除，全部降为纯视觉 / 轻接线。

### ⬜ 唯一依赖（已记入 `待确认信息.md` 第 1 条，需甲方确认）

甲方"默认有项目"靠后端 seed。**需确认真后端在新用户、零项目时 `GET /v1/projects` 是否也保证非空。** 若真后端可能返回空列表 → `ProjectGate` 会 return null 弹新建窗 → "首页全屏聊天"前提不成立，届时需在聊天窗前补一个 redesign 自己的新建项目引导（纯前端调 createProject）。**此条结论决定要不要补这一块，优先确认。**

### 数据时机（已确认，供形态切换/流式用）

| 数据 | 来源 | 时机 |
| --- | --- | --- |
| 助手文字 | SSE `text` 事件（字段 content） | 发消息后流式 |
| requirements/app_plan/report | SSE `state` 事件 | 分析中流式、done 之前 |
| screen_pngs/lap_system_dir | SSE `done` 事件 | 分析完成时一次性 |

形态切换（对话→项目面板）触发点：收到首个 `state`（有 requirements/app_plan/report 任一）或 `done`。自动出图/居中：`done` 带 screen_pngs。

## 三、分步执行计划（每步独立可运行、可验证；用户 OK 才进下一步）

> 顺序原则：先做"风险低、纯视觉、可独立验证"的，再做"接线重、影响时序"的。每步结束列出"本步已做 / 还没处理的窗口控件"。

### 阶段 0：地基——无边界画布组件 + 悬浮窗容器（纯视觉，不改数据流）

- 在 `redesign/ui/` 新增**手写的无边界画布组件**（不是 CSS 背景图）：
  - 自带视口变换状态 `{offsetX, offsetY, scale}`；鼠标按住画布空白处拖动 = 平移，滚轮 = 以光标为锚缩放。
  - 网格随 scale 自适应（放大变疏、缩小变密），强化"无限延伸"感。
  - **画布是完整全屏，无边框/无圆角/无可见边界**——看起来就是"整个屏幕是一张无限画布"，不能被看出是个窗口。
  - 图片**钉在画布坐标上**，与画布同一变换层，拖动画布时图片随之移动；单图可再拖拽/放大。
  - **两个悬浮窗（聊天 / 需求文档）独立于画布**，只是浮在画布之上、用于和后端交互的半透明控件，**不随画布平移缩放**。
- 把现有左抽屉（聊天）、右抽屉（ArtifactCanvas）改造成"悬浮在画布上的半透明窗口"容器（毛玻璃、圆角、阴影），**slot 内容不变**（仍是甲方 Thread / ArtifactCanvas）。【已完成】
- 本阶段先做出画布组件本身，用占位图验证拖拽/缩放/网格自适应手感；真实 Screens 接入与转场编排留后续阶段。
- 验证：画布可拖动平移、滚轮缩放、网格自适应、占位图随画布移动；现有功能（发消息、预览、切换器、语言、主题、新建项目）全部照常。
- 未处理：形态切换编排、需求文档独立窗、真实 Screens 接入——后续阶段。

### 编排转场时序（贯穿阶段 1/3/4 的一条连贯动画线，后端事件驱动）

用户要的核心观感是一段有先后顺序的过场，由后端事件驱动：

1. **触发**：Screens 图片生成（SSE `done` 带 screen_pngs）。
2. **聊天窗优雅左移**：原全屏聊天用自然变换移到左侧、缩成毛玻璃悬浮窗（阶段 1 形态切换）。
3. **全屏网格画布浮现**：聊天让位后，无边界画布淡入铺满全屏（画布在悬浮窗下层）。
4. **右侧需求文档浮现 + 流式**：右侧浮现需求文档悬浮窗，流式输出文字（阶段 3）。
5. **流式结束 → 图片自然弹出**：文字流完，Screens 图片以弹出动效出现在画布上（阶段 4）。

> 画布铺满全屏、在两个悬浮窗的下层；平移缩放只作用于画布与其上的图片，左右悬浮窗不受影响。

### 阶段 1：形态切换（接线读 canvasStore）

- 复用已有的 canvasStore 订阅（`previewReady` 那套思路），扩展为"形态状态"：初始态（纯对话居中）vs 项目操作态（画布+双悬浮窗）。
- 触发：收到首个 state 或 done → 从初始态过渡到项目操作态，中间欢迎文字隐去（CSS 隐藏，不卸载）。
- 聊天窗从"居中大输入"过渡为"左侧毛玻璃悬浮窗"，定比例。
- 验证：发消息→出内容→界面形态切换；切换器/语言/主题仍在。
- 未处理：首句建项目、需求文档流式独立窗、Screens 居中动画。

### 阶段 2：硬件设置入口（纯视觉，移位）

- 原 WelcomeTab 改名"硬件设置"，从 ArtifactCanvas 的 tab 里移出，改为项目操作面板上的一个按钮 → 点击弹出（毛玻璃弹窗，复用 ManualModal 风格）。
- WelcomeTab 组件本身不动（仍是甲方的硬件 UI + boards/pair-code 轮询），只换"入口位置"。
- 验证：硬件列表、配对码、刷新都正常；boards 10s 轮询照常。
- 未处理：需求文档流式、Screens 居中。

### 阶段 3：需求文档独立悬浮窗 + 流式 + 收起/拽出（纯视觉为主）

- 把 prd（需求/报告）+ slint（方案文本）合并成一个右侧悬浮窗，标签切换"需求文档 / 方案文本"。
- done 时：先浮现毛玻璃窗，流式输出文字内容，显示完再放图（图归阶段 4 的 Screens，本步先把文字流式做出来）。
- 后续新内容直接流式追加（只第一次等图）。
- 关闭 → 拽回右下角极简控件（CSS transform 动画，组件不卸载）；点控件 → 拽出恢复。
- 验证：内容流式出现、可关可开、关了后台仍在（再来数据不丢）。
- 未处理：Screens 居中画布。

> 已查证（供阶段3做流式用）：甲方 `requirements`/`report`/`app_plan` 是每次 SSE `state` 事件来时**整体替换** canvasStore 字段（不是逐字打字机）。所以"流式逐字显示"需在 redesign 层自己做（如对 canvasStore 内容做打字机动画展示），属纯视觉，不改甲方数据流。

### 阶段 4：Screens 居中浮现 + 画布定位（纯视觉）

- 等需求文档流式输出完 → screen_pngs 的图以浮现动画出现在画布中央。
- 左右悬浮窗（聊天 / 信息）定位在画布两侧，半透明。
- 验证：出图时机、居中动画、双窗悬浮布局；点击放大等原有交互保留。
- 未处理：无（视觉主体完成，后续是细节打磨）。

### 阶段 5：（条件性）无项目时的新建引导——仅当甲方真后端可能返回空项目列表才做

- **默认不做**。本阶段是否需要，取决于 `待确认信息.md` 第 1 条的甲方答复：
  - 若真后端保证新用户有默认项目 → **本阶段取消**，跟随甲方默认项目即可。
  - 若真后端可能返回空列表 → 在 `ProjectGate` 外加一个 redesign 自己的"新建项目引导"界面（纯前端调甲方 `createProject`），覆盖"无项目"场景，建完进入正常对话。
- 这步若要做，最易碰甲方时序，单独做、单独验证；失败要回退不卡死。
- 验证：模拟空项目场景 → 引导建项目 → 进入对话正常。

## 四、全程铁律（每步都遵守）

- 只改 `redesign/ui/` + CSS + 必要的 `redesign/bindings/` 接线；**不改甲方组件内部逻辑**。
- 显隐一律 CSS（translate/opacity/display），**绝不条件渲染卸载** Thread/ArtifactCanvas/MyRuntimeProvider/Composer。
- 接线只读已有 store、调已有方法（canvasStore / useProjectContext），**不自己 fetch、不造状态**。
- 未处理到的控件/窗口继续显示、能用；每步末尾报告"还剩什么没处理"。
- 后端切换器、诊断、语言、主题、预览/构建/硬件按钮等现有功能全程保持可用。
