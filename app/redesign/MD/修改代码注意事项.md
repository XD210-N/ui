# 修改代码注意事项

这是 `/redesign` 后续接手时必须先读的硬性约束。  
目标只有一个：**在不破坏现有前后端连接的前提下，只改界面外观、布局和交互体验。**

## 0. 当前实现状态

当前 `/redesign` 已经不是“静态视觉稿”，而是接了真实功能的重排版本：

- 中间主区保留真实 `Thread`
- 左侧项目/历史改成从左侧弹出的抽屉
- 右侧 `ArtifactCanvas` 改成从右侧弹出的面板
- 左下角有项目入口
- 左侧抽屉里有设置入口
- 设置里有语言子菜单和说明书入口
- 说明书是居中的毛玻璃弹窗，内部预留 `<video controls>`
- 默认语言是 `zh-TW`
- 当前语言入口是 5 种：`zh-TW / zh / en / ja / ko`
- 首页标题、副标题、设置文案、上传文案都走 `useStrings()`
- 明暗主题切换已接完：redesign 自管（未用 next-themes），作用域仅 redesign 子树，暗色目前是占位配色（见 `MYWORK.md` 5.1 节）

这意味着后续修改时，不能再把它当成三列静态原型来处理。

> 甲方上一版反馈指出的 5 个缺失项（发送按钮 / 对话运行时 / ArtifactCanvas / 文件上传 / 线程历史）现已全部真实接线，逐项核对见 `反馈.md` 顶部状态表。

## 1. 最重要的底线

1. 只改界面风格、布局、动效和位置，不改功能链路。
2. 不能模拟后端返回的数据。
3. 不能把真实组件替换成假组件。
4. 不能为了“好看”把功能入口删掉。
5. 不能让一个功能“先不做”就直接从页面上消失。
6. 后端当前没完善的内容，不要自己编造，保留空状态或占位说明。

## 2. 后端不完整时的处理方式

当前甲方后端仍在施工，所以前端只能基于现阶段已有接口和已有组件对接。

必须遵守：

- 只接现有代码里已经定义的接口、hook、store、runtime、primitive
- 如果接口暂时没有返回内容，不要 fake
- 如果数据为空，前端可以显示空状态
- 如果功能入口暂时想不清楚放哪里，先保留在首页、侧边栏或当前面板里，不要删除

一句话原则：

**前端写的是“对接现有工程”，不是“补一套假的后端”。**

## 3. 真实组件不能卸载

以下核心组件不要通过条件渲染直接删掉：

- `Thread`
- `ArtifactCanvas`
- `Composer` / 发送逻辑
- `ProjectProvider`
- `ProjectGate`
- `MyRuntimeProvider`
- `ThreadListPrimitive`
- `useProjectContext()`
- `useLocale()` / `useSetLocale()`

允许做的事：

- 改位置
- 改宽度
- 改透明度
- 改 `transform`
- 改遮罩
- 改动画

不允许做的事：

- 用 `show && <Component />` 把核心功能卸载掉
- 用静态卡片替换真实运行时组件
- 用 mock 输入框替换真实 composer
- 用假消息列表替换真实 thread

## 4. 隐藏和卸载不是一回事

正确做法是：

```tsx
<section className={rightOpen ? "translate-x-0" : "translate-x-full"}>
  {artifactSlot}
</section>
```

不要写成：

```tsx
{rightOpen && artifactSlot}
```

原因很直接：

- 卸载会丢状态
- 卸载会打断订阅
- 卸载会重置运行中请求
- 卸载会让历史线程、tab、日志、预览状态回到初始值

## 5. 视觉层和连接层分工

- `app/redesign/ui/` 只放布局和样式
- `app/redesign/bindings/` 只放真实功能接线
- 视觉组件不要直接写复杂业务逻辑
- 新按钮如果要触发原功能，必须接原来的 hook / store / primitive / runtime

## 6. 当前页面结构

当前设计已经确定为：

1. 默认首页以中间对话栏为主。
2. 左侧项目/历史区域默认收起。
3. 点击左下角按钮，左侧抽屉从屏幕左边弹出。
4. 点击对话区域空白处，左侧抽屉收回。
5. 点击右上角按钮，右侧预览画布从屏幕右边弹出。
6. 右侧展开时，中间区域压缩为左侧一小块。
7. 右侧关闭时，`ArtifactCanvas` 仍然保留在 React 树中。

## 7. 语言和说明书

- 当前默认语言是 `zh-TW`
- 当前语言列表是 `zh-TW / zh / en / ja / ko`
- 语言切换必须继续读写 `localStorage`
- 首页中间标题、副标题、按钮文案必须跟随语言变化
- 说明书按钮打开的是毛玻璃视频弹窗
- 甲方后续给视频时，只需要填入视频源，不要重新做一套说明系统

## 11. 项目化交互重构（进行中的大改方向，2026-06-13 起）

用户（视觉交互设计师）提出"以项目为核心"的高级交互重构，分阶段执行。**完整方案与分步计划见 [`项目化交互重构执行方案.md`](./项目化交互重构执行方案.md)**；副界面各视图的数据来源见 [`副界面四视图说明.md`](./副界面四视图说明.md)；具体改法见 [`前端视觉交互修改方案手册.md`](./前端视觉交互修改方案手册.md)。

核心需求（摘要）：

1. **以项目为核心**：初始页只有对话框（无项目）；用户发第一句话 → 立即建空项目，项目名=第一句话，左侧列表自动出现。
2. **形态切换**：后端返回 state/done（文字外内容）时，整个界面从"纯对话"变为"项目操作面板"，中间欢迎文字隐去。
3. **不左右分割**：左侧聊天窗做成**毛玻璃悬浮**在项目面板之上，定合适比例，苹果质感。
4. **硬件设置**：原"欢迎"tab 改名"硬件设置"，移到项目面板里按钮弹出。
5. **需求文档独立窗**：done 时右侧浮现毛玻璃窗，流式输出内容，显示完才出图；可关闭→拽回右下角控件→再拽出。**只是视觉隐藏，组件不卸载，后台一直在。**
6. **需求文档+方案文本合并**：用标签切换。
7. **Screens 居中**：等需求文档流式完→图以浮现动画出现在页面中央；整屏网格背景无边界画布，左右会话/信息窗是悬浮其上的半透明控件。

本次重构的**铁律**（除本文件既有底线外，额外强调）：

- 分阶段执行，**每阶段用户自行运行验证、说 OK 才进下一步**。
- **未处理到的控件/窗口必须继续显示、能正常用**；每阶段末尾报告"还剩什么没处理"。
- 已查证的关键时序：甲方"一进就能聊"靠**后端预置默认项目**（mock seed 了 demo-project），前端自动打开第一个。**决定跟随此方案——默认已有项目，不做"发第一句才建项目"的时序倒置**，首页改毛玻璃悬浮+全屏聊天属纯视觉，新建项目功能保留。唯一依赖：真后端是否保证新用户有默认项目（见 `待确认信息.md` 第 1 条），若否才需补无项目引导（阶段 5 条件性）。
